# 文章ルール

スライドの文は、聞き手が 1 回読んで意味を取れるように書く。目安は、投影用なら 1 枚 3 秒、配布用なら 1 回の通読。
書き手は文脈を知っているので、自分の文の省略に気付けない。書いたら下の 8 項目で確かめ、最後に `cold-read.md` で初見の読み手に読ませる。

## 1 回で意味が取れるかの 8 項目

語の抜けと、文やスライドのつながりの抜けを分けて確かめる。

### 語の 6 項目

| 項目           | 問い                                                     | 前 → 後                                                                            |
| -------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 主体・所有者   | 誰の・何の、が書いてあるか。誰の主張か（記事か発表者か） | 会話ログ → AI エージェントとの会話ログ / 多くの人は → 著者の見立てでは、多くの人は |
| 量の中身       | 何の時間・何の失敗か。単位・分母・期間はあるか           | 失敗 → ツール呼び出しの失敗回数 / 16.7% → 12 回中 2 回                             |
| 動詞の相手     | 何を何と比べるか、何をどうするか                         | 比べられる → Skill ごとに並べて比べられる / 出す → デプロイする                    |
| 内輪の語       | ペルソナの聞き手が知っている語か                         | ハーネス → Skill や hook などの仕組み                                              |
| 数と列挙       | 書いた数と、並べた項目の数が合っているか                 | 3 つ並べて「4 点」 → 数を外すか、4 つ並べる                                        |
| 「もの・こと」 | 具体的な語や動詞に戻せないか                             | 直すもの → Skill の説明文・手順・権限                                              |

1 か所直したら、同じ語が他のスライドに残っていないかを探し、同じ基準でまとめて直す。

### 文・スライドの 2 項目

| 項目           | 問い                                                                                                   | 前 → 後                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 言い切りと数字 | 見出しの言い切り（上がった・半分以上・高い）を、載せた数字で言えるか。多い・少ないを比べる基準はあるか | 半分以上が原因（表では 62 件中 28 件） → 62 件中 28 件が原因 |
| つながり       | 例や箇条は見出しの主張を支えているか。前のスライドと矛盾して見えないか                                 | 仕組みが逆の例を 2 つ並べる → 例ごとに何を示すかを頭に書く   |

語の抜けは、その語を足せば直る。文・スライドの抜けは、見出しを数字に合わせて弱めるか、例と主張をつなぐ文を足して直す。
足しきれない根拠や前提はノートに書く。

## 短くするときに削ってよい語・削ってはいけない語

lint の上限を超えたときも、意味を運ぶ語は削らない。

- 削らない: 語の 6 項目で補った語（主体・対象・単位・比較の相手）、理由や対比を表す語（ので・ただし）
- 削る: 修飾の重複、2 つ目の主張（別のスライドかノートへ）、「〜することができる」「〜を行う」などの冗長な言い回し
- それでも収まらなければ、`design-rules.md` の「文字を減らす順序」に従う

## 書き換え例

### 主張を 1 文で言うスライド（statement）

前:

> 会話ログでは見えない「時間・コスト・失敗」を
> Skill やツールの単位で比べられるようになった

- 誰の会話ログか、何にかかった時間か、何の失敗か、何と何を比べるのかが無い
- 「会話ログでは見えない」（なぜ要るか）と「比べられる」（何ができるか）の 2 つの主張が 1 文に入っている

後:

> 所要時間・API 利用料・ツールの失敗回数を
> Skill ごとに並べて比べられるようにした

「会話ログには残らない」は理由なので、次のスライドで説明する。

### 表で裏付ける見出し

- 前: 見送った候補は、画面・保存期間・外部送信のどれかが合わなかった（表の 4 行目の理由「構成要素が多い」は、3 つのどれにも入らない）
- 後: 4 つの条件を全部満たすのは、1 コンテナで揃う otel-lgtm だけだった（表の各行の理由の頭に、欠けた条件を 1 つずつ書く）

見出しで分類を挙げたら、表の行がすべてその分類に入るかを確かめる。

### 数字で裏付ける見出し

- 前: 半分以上はルールではなく、コマンドの書き方が原因
  （表では、書き方が原因は 16 + 8 + 4 = 28 件。半分を超えるのは「確認すべき」書き込みの 5 件まで足したとき）
- 後: 確認 62 件のうち 28 件は、ルールではなくコマンドの書き方が原因
- 前: 却下理由を条件に足すと、Neovim の採用率が上がった（表では 74% → 87% のあと、9 月以降は 73%）
- 後: 却下理由を条件に足した 8 月は、Neovim の採用率が 74% から 87% に上がった

見出しの数や割合は、表の数字から計算し直してから書く。途中で戻った数字は、上がった期間を見出しに入れる。

### 例で裏付ける箇条

- 前: 見出し「できると信じる気持ちは育てられる」の下に、次の 2 つを説明なしで並べる
  - 未解決の問題を宿題と思い込んだ学生が、2 問とも解いた（無理だと知らなかったから挑めた）
  - 1 マイル 4 分の壁が破られると、他の選手も続いた（前例を見て、できると信じた）
- 後: 例ごとに、何を示すかを頭に書く（「無理だと知らなければ挑める: 〜」「前例を見ればできると信じられる: 〜」）

例を並べたら、それぞれが見出しのどこを支えるかを 1 語で言えるかを確かめる。

### まとめの 1 行

- 前: コマンドとパスが平文で残るので、共有先へ移すかは指標が固まってから決める
- 後: コマンドとパスが平文で記録されるので、チームで集計する基盤へ送るかは、使う指標が固まってから決める

何を「移す」のか（記録したデータ）と、どこへ・なぜ（チームで集計する基盤）が書かれていなかった。
