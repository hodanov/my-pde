# Glance test（初見の人の目が行く所のテスト）

書き手は見てほしい所を知っているので、自分の図でそこに目が行くかを判断できない。
文脈を持たない読み手にスライドの画像だけを見せ、どこに目が行ったかを聞いて、骨子で決めた見てほしい所と照らし合わせる。

## 対象

Workflow の Step 3 で見てほしい所を決めたスライド（図・グラフ・スクショ・表・コード・`number`）だけ。
文字だけのスライドは cold read で確かめている。

## 渡すもの・渡さないもの

- 渡す: 聞き手のペルソナ、用途、対象スライドの PNG とぼかした PNG のパス
- 渡さない: 見てほしい所、発表者ノート、会話の経緯（答えを渡すとテストにならない）

PNG は `scripts/render_deck.sh <deck.md> png` で作る。ぼかした PNG は、同じディレクトリの `blur/` に同じ名前で入る。
ImageMagick が無くて `blur/` ができないときは、1 問目も元の画像で答えさせる。

## プロンプト

`{...}` を埋めて渡す。`{見せ方}` は、投影用なら「発表中に 1 枚あたり 3 秒ほど見るもの」、配布用なら「発表者なしで 1 回だけ見るもの」。

```text
あなたは次の聞き手です。
{ペルソナ}

これから見せるスライドは、{見せ方}です。
下に並べた画像ファイルだけを開いて答えてください。ほかのファイルは開かないでください。

スライドごとに、次の 3 つを答えてください。
1. 目立つ所: ぼかした画像を先に開き、見出しの文字を除いて、一番目立つ所と 2 番目に目立つ所を、位置と見た目で（例: 中央の紫の横長の棒）
2. 3 秒で取れたこと: 元の画像を開き、見出しの次に目が行った所と、このスライドが言いたいことを 1 文で
3. 読めない所: 小さくて、または薄くて読めない文字と、どこを見ればいいか迷った所（無ければ「なし」）

{スライドごとに、番号・元の画像のパス・ぼかした画像のパス}
```

## 結果の読み方

- 目立つ所が、骨子で決めた見てほしい所と違う → `visual-rules.md` の 5 項目の「1 か所」「余計なもの」で直す
- 言いたいことが見出しとずれる → 証拠が見出しを支えていない。「証拠の型を選ぶ」で型を選び直すか、見出しを証拠に合わせる
- 読めない文字がある → 切り抜くか拡大する（lint を通っていても）
- どこを見ればいいか迷った → 見てほしい所を枠で囲むか、隣に数字を大きく書く

直したら lint と PNG を再実行し、直したスライドだけもう 1 回見せる。それ以上は回さない。
