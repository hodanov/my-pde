# Cold read（初見の読み手テスト）

書き手は文脈を知っているので、自分の文の省略や、話の筋の飛びに気付けない。
会話の文脈を持たない読み手に文字だけを読ませ、言い換えと推測した語から、伝わっていない所を見つける。

テストは 2 回行う。

| 段階          | いつ                        | 渡すもの                           |
| ------------- | --------------------------- | ---------------------------------- |
| A. 骨子ゲート | 本文を書く前（見出しだけ）  | ペルソナ、見出しの連鎖             |
| B. 最終       | `check` が通り build する前 | ペルソナ、見える文字だけのスライド |

どちらも、会話を引き継がない新しいサブエージェントに渡す（Claude Code なら `general-purpose`。fork は会話を引き継ぐので使わない）。
各スライドで伝えたいこと、発表者ノート、`focus`、会話の経緯は渡さない。答えを渡すとテストにならない。

`{見せ方}` は、投影用なら「発表中に 1 枚あたり 3 秒ほど見るもの」、配布用なら「発表者なしで 1 回だけ読むもの」。

## A. 骨子ゲート

`scripts/deck.sh outline <spec> --headlines` の出力を渡す。
見出しだけで話の筋が通り、主張に行き着くかを確かめる。ここで直すほうが、本文を書いた後に直すより安い。

```text
あなたは次の聞き手です。
{ペルソナ}

これから、発表のスライドの見出しだけを順に見せます。
ファイルやツールは使わず、下の見出しだけを読んで答えてください。

1. 発表全体の主張を 2 文で言い換えてください。
2. 見出しの並びで、話の筋が飛んでいる所、前後で矛盾して見える所を挙げてください（無ければ「なし」）。
3. 意味を推測で補った語句と、補った意味を挙げてください。自信があっても挙げてください。

{見出しの連鎖}
```

### 骨子ゲートの結果の読み方

- 1 の言い換えが spec の `deck.claim` とずれる → 見出しの並びか章の結論を直す。主張を支える見出しが足りないか、別の話が混ざっている
- 2 で挙がった所 → 間に説明のスライドを足すか、見出しを言い切りに直す
- 3 の推測した語 → ペルソナが知らない語なら言い換える。知っている語なら直さない（`audience.knows` に書いてあるか確かめる）

直したら、もう 1 回だけ骨子ゲートを行う。それ以上は回さない。

## B. 最終

`scripts/deck.sh text <spec>` の出力（見える文字だけ。ノートは含まない）を渡す。

```text
あなたは次の聞き手です。
{ペルソナ}

これから見せるスライドは、{見せ方}です。
ファイルやツールは使わず、下の文字だけを読んで答えてください。画像の中身は見えません。

スライドごとに、次の 3 つを答えてください。
1. 言い換え: このスライドが言いたいことを 1 文で
2. 推測した語: 意味を推測で補った語句と、補った意味。自信があっても挙げる
3. 残った疑問: スライドを読んでも分からないこと（2 つまで。無ければ「なし」）

最後に、見出しだけを順に読んで、発表全体の主張を 2 文で言い換えてください。

{見える文字だけのスライド}
```

### 最終の結果の読み方

- 言い換えが、そのスライドの見出しの意図とずれる → 見出しか本文を直す
- 推測した語や、誰の・何の・いつのを問う疑問がある → `writing-rules.md` の語の 6 項目で補う。ペルソナが知っている語なら直さない
- 見出しの言い切りが数字と合わない、例が主張を支えない、前のスライドと矛盾して見える → `writing-rules.md` の文・スライドの 2 項目で直す
- 仕組みの詳細や反論への疑問 → スライドの欠陥ではない。ノートで答えているかを確かめ、無ければノートに書く
- 最後の主張の言い換えが `deck.claim` とずれる → 骨子（見出しの並び）を直す

直したら、直したスライドだけもう 1 回 cold read する。それ以上は回さない。
